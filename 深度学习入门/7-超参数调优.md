## 引言：为什么需要调优？

在前面的章节，我们学习了网络结构、训练技巧、优化器、损失函数等知识。但实际训练模型时，你会发现：

**比喻：做菜的艺术**

想象你按照菜谱做一道菜：

```
菜谱（模型架构）：3层CNN + 2层全连接

- 学习率适中 → 火候刚好

同样的菜谱，调料比例决定成败！
```

## 7.1 超参数调优基础

### 7.1.1 什么是超参数？

**参数 vs 超参数**

```
参数（Parameters）：
- 模型自己学习的（如权重、偏置）
- 通过梯度下降更新
- 例如：w₁=0.5, b=0.3

超参数（Hyperparameters）：
- 人为设定的（训练前就要决定）
- 不通过梯度下降学习
- 例如：学习率=0.001, batch_size=32
```

**比喻：种树**

```
参数（树的生长）：
- 树枝往哪长
- 根扎多深
- 自然生长，不需要人为干预

超参数（种植条件）：
- 浇水频率（学习率）
- 施肥量（batch size）
- 修剪策略（正则化）
- 人为设定，影响生长效果
```

### 7.1.2 常见超参数分类

#### 1. 最重要的超参数 ⭐⭐⭐⭐⭐

**学习率 (Learning Rate)**

```
影响：最大！调错了，模型根本学不动

典型范围：[1e-5, 1e-1]

过大：震荡、发散、NaN
过小：学习太慢、停滞
刚好：稳定收敛

比喻：油门力度
太猛：车失控
太轻：走不动
```

**批量大小 (Batch Size)**

```
影响：收敛速度和泛化性能

典型值：32, 64, 128, 256

过大：收敛快，但泛化差；需要更多内存
过小：泛化好，但收敛慢；梯度噪声大
适中：平衡

比喻：一次搬多少砖
1块：累死，但能精确调整
100块：快但笨重
```

#### 2. 重要的超参数 ⭐⭐⭐⭐

**网络结构**
- 层数：深度
- 每层神经元数：宽度
- 激活函数类型

**正则化参数**
- Dropout率：0.1 ~ 0.5
- Weight Decay：1e-5 ~ 1e-2
- L2正则化系数

**优化器参数**
- Adam的β₁, β₂
- Momentum的β

#### 3. 次要超参数 ⭐⭐⭐

**学习率调度**
- 衰减策略
- Warm-up步数

**数据增强**
- 增强强度
- 增强类型

**训练相关**
- Epoch数
- 梯度裁剪阈值

### 7.1.3 调优的目标

**不是最小化训练损失！**

**比喻：考试vs实战**

```
错误目标（过拟合）：
学生把所有练习题答案背下来
→ 练习题100分（训练集）
→ 考试60分（验证集）
→ 实战50分（测试集）

正确目标（泛化）：
学生理解知识原理
→ 练习题85分
→ 考试80分
→ 实战75分

目标：最大化验证集性能！
```

**数据集划分：**

```
总数据：10000个样本

训练集（70%）：7000样本
- 用于训练模型
- 更新权重

验证集（15%）：1500样本
- 用于调参
- 选择最佳超参数
- 早停判断

测试集（15%）：1500样本
- 最终评估
- 只用一次！
- 报告最终性能
```

**为什么需要验证集？**

```
如果只有训练集和测试集：
1. 在测试集上调参
2. 测试集性能越来越好
3. 但模型"记住"了测试集
4. 真实数据上表现差

验证集的作用：
- 模拟真实数据
- 避免过拟合到测试集
- 保证测试集的"纯洁性"
```

## 7.2 超参数搜索方法

### 7.2.1 手动调参：新手入门

**优点：**
培养直觉
理解每个参数的作用
适合学习阶段

**缺点：**
耗时耗力
容易陷入局部思维
经验依赖强

**比喻：开车学习**

```
新手（手动调参）：
每个按钮都要试一试
油门、刹车、方向盘...
慢慢建立手感

老司机（自动调参）：
经验丰富，快速决策
但新手阶段必不可少
```

**建议顺序：**

```
第1步：固定其他参数，只调学习率
找到一个能让loss下降的学习率

第2步：调整batch size
在GPU内存允许的范围内，尽量大一些

第3步：调整正则化
如果过拟合：增大dropout/weight decay
如果欠拟合：减小正则化

第4步：调整网络结构
层数、宽度

第5步：微调其他参数
```

### 7.2.2 网格搜索 (Grid Search)

**原理：暴力枚举所有组合。**

**比喻：地毯式搜索**

```
场景：在公园里找丢失的钥匙

网格搜索策略：
把公园划分成10×10的网格
每个格子都仔细搜索
一定能找到（如果钥匙在公园里）

优点：不会遗漏
缺点：太慢了！
```

**示例：**

```python
学习率：[0.1, 0.01, 0.001]  # 3个选项
Batch size：[32, 64, 128]    # 3个选项
Dropout：[0.2, 0.3, 0.5]     # 3个选项

总共组合：3 × 3 × 3 = 27种
每种都要训练一遍 → 耗时27倍

结果：
尝试所有27种组合
选择验证集性能最好的
```

**优点：**
简单直观
可以并行（每个组合独立训练）
不会遗漏搜索空间中的点

**缺点：**
组合爆炸：4个参数×5个值 = 625种组合！
浪费资源：很多组合明显不好
不适合连续参数

**适用场景：**
- 参数数量少（≤3个）
- 计算资源充足
- 需要完整对比

### 7.2.3 随机搜索 (Random Search)

**原理：随机采样参数组合。**

**比喻：撒网式搜索**

```
场景：还是找钥匙

随机搜索策略：
在公园里随机选20个点搜索
不保证找到，但覆盖面广

优点：快，能探索更多区域
缺点：可能运气不好，错过最佳点
```

**为什么比网格搜索好？**

**关键洞察：不是所有参数都同等重要！**

```
假设有2个参数：

参数A（重要）：学习率
参数B（不重要）：某个不影响性能的参数

网格搜索：
学习率：[0.1, 0.01, 0.001]  3个值
参数B：[1, 2, 3, 4, 5]       5个值
总共：3×5 = 15次尝试
但只尝试了3种学习率！

随机搜索：
15次随机采样
可能尝试15种不同的学习率！
更可能找到最佳学习率
```

**可视化对比：**

```
网格搜索（9次尝试）：
参数B  ×  ×  ×
       ×  ×  ×
       ×  ×  ×
       ↑
    参数A（只尝试3个值）

随机搜索（9次尝试）：
参数B    × ×  
       ×    ×
      ×   ×  
         ×  ×
       ↑
    参数A（尝试9个不同值！）
```

**实现：**

```python
import random

搜索空间：
lr: [1e-5, 1e-1] (对数空间)
batch_size: [16, 256]
dropout: [0.0, 0.5]

随机采样100次：
for i in range(100):
    lr = 10 ** random.uniform(-5, -1)  # 对数均匀采样
    batch_size = random.choice([16, 32, 64, 128, 256])
    dropout = random.uniform(0.0, 0.5)
    
    训练模型(lr, batch_size, dropout)
    记录验证集性能
    
选择最佳组合
```

**优点：**
比网格搜索高效得多
能探索连续空间
对重要参数采样更密集（自然特性）
易于并行

**缺点：**
不保证找到最优
可能需要大量尝试
对极端值采样不足

**适用场景：**
- 参数较多（3-6个）
- 不确定参数重要性
- 预算有限（相对于网格搜索）

**推荐配置：**

```
搜索次数：
- 少量参数（2-3个）：50-100次
- 中等参数（4-5个）：100-200次
- 较多参数（6+个）：200+次
```

### 7.2.4 贝叶斯优化 (Bayesian Optimization)

**原理：基于之前的结果，智能选择下一个尝试点。**

**比喻：有经验的猎人**

```
场景：打猎

随机搜索（新手猎人）：
随机在森林里走
碰运气找猎物

贝叶斯优化（老猎人）：
1. 观察动物足迹（历史结果）
2. 推测动物可能在哪（建模）
3. 去最可能的地方（选择下一个点）
4. 根据新发现更新判断
5. 重复

越猎越准，不浪费时间在明显不好的地方
```

**工作流程：**

```
初始阶段：
随机尝试几个点（如5个）
建立初步认识

迭代阶段：
1. 根据已有结果，建立"性能地形图"
   - 哪些区域性能好
   - 哪些区域性能差
   - 哪些区域不确定

2. 选择下一个点：平衡两个目标
   - Exploitation（开发）：去已知好的区域附近
   - Exploration（探索）：去不确定的区域

3. 训练模型，记录结果

4. 更新"地形图"

5. 重复2-4
```

**示例：寻找最佳学习率**

```
尝试1: lr=0.1   → 性能=0.6
尝试2: lr=0.001 → 性能=0.8
尝试3: lr=0.01  → 性能=0.85

贝叶斯优化推理：
"0.01表现最好，附近可能更好"
"但0.001-0.01之间还没充分探索"

尝试4: lr=0.005 → 性能=0.87  更好！
尝试5: lr=0.003 → 性能=0.86
尝试6: lr=0.007 → 性能=0.88  更好！

聚焦在0.005-0.01之间精细搜索
```

**优点：**
样本效率高：30-50次尝试可能超过随机搜索100次
智能决策：不浪费时间在差的区域
自适应：根据结果调整策略

**缺点：**
不易并行（需要看前面结果才能决定下一步）
高维空间效果下降
实现复杂

**工具：**

```python
# 使用Optuna库
import optuna

def objective(trial):
    # 定义搜索空间
    lr = trial.suggest_loguniform('lr', 1e-5, 1e-1)
    batch_size = trial.suggest_categorical('batch_size', 
                                           [32, 64, 128])
    dropout = trial.suggest_uniform('dropout', 0.0, 0.5)
    
    # 训练模型
    val_acc = train_model(lr, batch_size, dropout)
    
    return val_acc  # 优化目标

# 运行优化
study = optuna.create_study(direction='maximize')
study.optimize(objective, n_trials=50)

# 最佳参数
best_params = study.best_params
```

**适用场景：**
- 计算成本高（训练一次很慢）
- 参数数量中等（3-10个）
- 需要高效找到较好的配置

| 方法 | 效率 | 样本需求 | 并行性 | 适用场景 | 推荐指数 |
|------|------|---------|--------|----------|---------|

**实战建议：**

```
阶段1：快速原型（手动调参）
- 先让模型能跑起来

- 时间：1-2小时

- 扩大搜索范围
- 尝试50-100组参数

阶段3：精调（贝叶斯优化）
- 在粗调基础上精细调整
- 尝试30-50组参数

- 在测试集上评估
- 只评估最佳配置
- 确保没有过拟合到验证集
```

## 7.3 超参数调优技巧

### 7.3.1 对数空间搜索

**问题：学习率的范围很大**

```
学习率可能的值：
0.00001, 0.0001, 0.001, 0.01, 0.1

线性采样：
random.uniform(0.00001, 0.1)
→ 几乎总是采样到接近0.1的值
→ 小学习率探索不足

对数采样：
10 ** random.uniform(-5, -1)
→ 每个数量级均匀采样
→ 0.00001-0.0001, 0.0001-0.001, ... 都有机会
```

**比喻：财富分布**

```
线性采样：
在0-1000万之间随机选一个人的财富
大部分人财富接近1000万（错误！）

对数采样：
考虑财富的数量级
0-10万：一些人
10-100万：一些人
100-1000万：一些人
符合现实分布
```

**对数空间适用参数：**

```
学习率：[1e-5, 1e-1]
Weight Decay：[1e-5, 1e-2]
Dropout（有时）：[0.01, 0.5]

Batch Size：[32, 256]（通常线性或2的幂）
层数：[2, 10]（离散，线性）
```

### 7.3.2 从粗到细的策略

**比喻:望远镜寻找星星**

```
第1步：粗略扫描（大范围，低精度）
学习率：[1e-5, 1e-1]  采样20次
→ 发现0.001-0.01之间表现好

第2步：聚焦精调（小范围，高精度）
学习率：[0.001, 0.01]  采样20次
→ 发现0.003最佳

第3步：微调（极小范围，极高精度）
学习率：[0.002, 0.004]  采样10次
→ 确定0.0028最佳
```

**实施方案：**

```
粗调（Coarse Tuning）：
- 搜索空间大
- 采样密度低
- 目标：找到"好"的区域
- 例如：50次随机搜索

精调（Fine Tuning）：
- 搜索空间小（粗调结果±20%）
- 采样密度高
- 目标：找到"最好"的点
- 例如：30次贝叶斯优化

微调（Micro Tuning）：
- 极小范围（精调结果±5%）
- 网格搜索
- 目标：确认最终配置
- 例如：9次网格搜索
```

### 7.3.3 一次只调一个参数

**问题：同时调多个参数，分不清谁的功劳**

```
实验A：
学习率=0.01, Batch=64, Dropout=0.3
准确率：85%

实验B：
学习率=0.001, Batch=128, Dropout=0.5
准确率：88%

问题：性能提升是因为...
- 学习率降低？
- Batch增大？
- Dropout增大？
- 还是三者协同？
分不清！
```

**单变量控制法：**

```
基线：
学习率=0.01, Batch=64, Dropout=0.3
准确率：85%

实验1（只改学习率）：
学习率=0.001, Batch=64, Dropout=0.3
准确率：87%  → 学习率降低有帮助

实验2（只改Batch）：
学习率=0.01, Batch=128, Dropout=0.3
准确率：85.5%  → Batch影响不大

实验3（只改Dropout）：
学习率=0.01, Batch=64, Dropout=0.5
准确率：86%  → Dropout增大略有帮助

结论：
学习率影响最大！
优先优化学习率
```

**调参顺序（重要到次要）：**

```
1. 学习率 ⭐⭐⭐⭐⭐
   影响最大，优先调整

2. 网络结构 ⭐⭐⭐⭐
   层数、宽度

3. Batch Size ⭐⭐⭐⭐
   受GPU内存限制

4. 正则化参数 ⭐⭐⭐
   Dropout、Weight Decay

5. 学习率调度 ⭐⭐⭐
   衰减策略、Warm-up

6. 数据增强 ⭐⭐
   增强类型和强度

7. 优化器参数 ⭐
   通常用默认值
```

### 7.3.4 学习率范围测试 (LR Range Test)

**快速找到合适的学习率范围。**

**方法：**

```
1. 从极小学习率开始（如1e-8）
2. 每个batch指数增长学习率
   lr = lr × 1.1
3. 记录每个学习率对应的loss
4. 绘制 loss vs learning rate 曲线
5. 观察曲线特征

典型曲线：
Loss
 │  ╲___
 │      ╲_
 │         ╲__
 │            ╲___╱← loss开始上升
 │                 /
 │                /
 └──────────────────→ Learning Rate
    ↑    ↑     ↑
   太小  好  太大

选择建议：
- 最优lr：loss下降最快的点
- 保守选择：最优lr的1/10
- 激进选择：最优lr的1/3
```

**解读曲线：**

```
特征1：Loss不下降（lr太小）
Loss始终在高位
→ 学习率太小，学不动

特征2：Loss快速下降（合适）
Loss下降最快的区域
→ 这就是好的学习率范围

特征3：Loss震荡上升（lr太大）
Loss不降反升
→ 学习率太大，发散了

特征4：Loss先降后升（常见）
有明显的最低点
→ 选最低点之前的lr
```

**实现：**

```python
lr_finder = LRFinder(model, optimizer, criterion)
lr_finder.range_test(train_loader, 
                     start_lr=1e-8, 
                     end_lr=10, 
                     num_iter=100)
lr_finder.plot()  # 绘制曲线
```

**优点：**
快速（只需训练100-200个batch）
直观（一张图就能看出来）
实用（能找到合适范围）

### 7.3.5 早停与检查点

**Early Stopping：适时停止训练**

```
监控验证集损失：

Epoch 1-10：验证集loss下降（好！）
Epoch 11-15：验证集loss停止下降（耐心等待）
Epoch 16-20：验证集loss开始上升（过拟合！）

早停策略：
如果连续N个epoch（如5个）验证集loss没提升
→ 停止训练
→ 恢复到最好的那个epoch的模型
```

**比喻：烤蛋糕**

```
烤蛋糕：
前20分钟：蛋糕逐渐成型（训练集loss下降）
20-25分钟：表面金黄（验证集最佳）
25-30分钟：开始焦糊（过拟合）

早停：
在表面金黄时停止
不要烤到焦糊
```

**Checkpoint：保存最佳模型**

```python
最佳验证准确率 = 0
耐心计数器 = 0
最大耐心 = 5

for epoch in range(100):
    训练一个epoch
    验证集准确率 = 在验证集上评估
    
    if 验证集准确率 > 最佳验证准确率:
        最佳验证准确率 = 验证集准确率
        保存模型("best_model.pth")
        耐心计数器 = 0
    else:
        耐心计数器 += 1
    
    if 耐心计数器 >= 最大耐心:
        print("早停！")
        break

加载最佳模型("best_model.pth")
```

**注意事项：**

```
监控验证集，不是训练集
保存最佳模型，而不是最后一个
耐心值不要太小（至少5）
结合学习率调度使用

不要在训练集上早停
不要每个epoch都保存（浪费时间）
```

## 7.4 模型调试：诊断与解决

### 7.4.1 训练不动的问题

#### 问题1：Loss不下降 / Loss是NaN

**症状：**

```
Epoch 1: Loss = 2.5
Epoch 2: Loss = 2.5
Epoch 3: Loss = 2.5
...
或者
Epoch 1: Loss = 2.5
Epoch 2: Loss = NaN
```

**可能原因与解决方案：**

**原因1：学习率太大 ⭐⭐⭐⭐⭐**

```
诊断：
- Loss突然变NaN
- Loss震荡不降
- 梯度值很大（用TensorBoard查看）

解决：
学习率减小10倍
使用梯度裁剪
使用Adam代替SGD（更稳定）

示例：
lr = 0.1  → Loss=NaN
lr = 0.01 → 正常训练
```

**原因2：学习率太小 ⭐⭐⭐⭐**

```
诊断：
- Loss极其缓慢下降
- 训练10个epoch，loss几乎不变

解决：
学习率增大10倍
使用LR Range Test找合适范围

示例：
lr = 0.0001  → Loss=2.5（不动）
lr = 0.001   → Loss正常下降
```

**原因3：权重初始化不当 ⭐⭐⭐**

```
诊断：
- 从第1个epoch开始loss就是NaN
- 或者loss停在一个固定值

解决：
使用标准初始化（Xavier、He初始化）
检查是否用了BatchNorm（通常能缓解）

错误示例：
weights = torch.zeros(...)  # 所有权重是0！

正确示例：
weights = torch.nn.init.kaiming_normal_(...)
```

**原因4：数据预处理问题 ⭐⭐⭐⭐**

```
诊断：
- 查看输入数据的范围

常见错误：
图像像素值在[0, 255]，没有归一化
标签编码错误（标签是2但只有2个类）
数据加载顺序错误

解决：
图像归一化到[0,1]或[-1,1]
检查标签：从0开始，连续
打印几个batch的数据，人工检查

检查：
print("输入范围:", data.min(), data.max())
print("标签:", labels)
```

**原因5：模型有bug ⭐⭐⭐⭐**

```
诊断步骤：
1. 在小数据集（10-100个样本）上测试
2. 模型应该能过拟合小数据

如果小数据都拟合不了：
→ 模型有bug！

常见bug：
激活函数位置错误
层与层连接错误
损失函数不匹配（分类用了MSE）
梯度没有流动（某些层被冻结）

解决：
打印模型结构
检查每层输出shape
确认梯度流动（requires_grad=True）
```

**排查流程：**

```
第1步：简化问题
- 只用10个样本
- 简化模型（1-2层）
- 能过拟合吗？

第2步：检查数据
- 数据范围正常吗？
- 标签正确吗？
- 可视化几个样本

第3步：检查模型
- 打印模型结构
- 检查每层输出shape
- 梯度流动正常吗？

第4步：调整学习率
- 使用LR Range Test
- 从小到大尝试

第5步：换优化器
- 试试Adam（更鲁棒）
- 加上梯度裁剪
```

### 7.4.2 过拟合问题

**症状：**

```
训练集：准确率95%
验证集：准确率60%

典型曲线：
准确率
 │ ╱────训练集（一直上升）
 │╱
 │     ╱──验证集（先升后降）
 │    ╱  
 │___╱
 └──────────→ Epoch
```

**比喻：死记硬背**

```
学生A（过拟合）：
把所有练习题答案背下来
练习题：100分
考试：60分（题目变了，不会做）

学生B（正常）：
理解知识原理
练习题：90分
考试：85分（能灵活应用）
```

**解决方案（按推荐顺序）：**

#### 方案1：增加数据 ⭐⭐⭐⭐⭐

```
最根本的解决方法！

收集更多数据
数据增强（旋转、翻转、裁剪）
使用预训练模型（相当于更多数据）

比喻：
题目做得多，自然学得好
数据多，就不容易死记硬背
```

#### 方案2：增强正则化 ⭐⭐⭐⭐

```
2.1 增大Dropout
dropout = 0.3 → 0.5

2.2 增大Weight Decay
weight_decay = 0.001 → 0.01

2.3 添加数据增强
增加旋转、色彩扰动等

2.4 使用Label Smoothing
```

#### 方案3：简化模型 ⭐⭐⭐⭐

```
模型太复杂 → 记忆能力太强 → 过拟合

解决：
减少层数
减少每层神经元数
使用更简单的架构

示例：
原模型：5层，每层512个神经元
简化：3层，每层256个神经元
```

#### 方案4：Early Stopping ⭐⭐⭐⭐

```
在验证集性能达到最佳时停止
不要继续训练到过拟合
```

#### 方案5：集成学习 ⭐⭐⭐

```
训练多个模型，取平均

单个模型：过拟合
多个模型平均：减轻过拟合

比喻：
一个学生可能偏科
多个学生投票，更可靠
```

**诊断过拟合的程度：**

```
轻度过拟合（可接受）：
训练集：92%
验证集：90%
差距：2%  → 还好

中度过拟合（需要改进）：
训练集：95%
验证集：85%
差距：10%  → 需要正则化

严重过拟合（必须解决）：
训练集：99%
验证集：60%
差距：39%  → 模型基本无用
```

### 7.4.3 欠拟合问题

**症状：**

```
训练集：准确率70%
验证集：准确率68%

都很低！
```

**比喻：学习能力不足**

```
学生能力不够：
既做不好练习题（训练集）
也考不好试（验证集）

不是不努力，是能力不行
需要提升能力！
```

**解决方案：**

#### 方案1：增加模型容量 ⭐⭐⭐⭐⭐

```
模型太简单 → 表达能力不足 → 欠拟合

解决：
增加层数
增加每层神经元数
使用更复杂的架构（如ResNet）

示例：
原模型：2层CNN
改进：6层CNN，加残差连接
```

#### 方案2：训练更久 ⭐⭐⭐⭐

```
可能还没收敛

解决：
增加epoch数
降低学习率，训练更长时间
使用学习率调度

注意：
如果训练100 epoch后loss还在下降
→ 继续训练
如果loss已经平了
→ 不是训练时间问题
```

#### 方案3：减少正则化 ⭐⭐⭐

```
正则化太强 → 限制了模型学习能力

解决：
减小Dropout（0.5 → 0.2）
减小Weight Decay（0.01 → 0.001）
减少数据增强强度
```

#### 方案4：检查数据和任务 ⭐⭐⭐⭐⭐

```
可能原因：
数据质量太差（标注错误）
任务本身很难（数据不足以区分类别）
特征提取不足

解决：
清洗数据
添加特征工程
使用预训练模型
```

### 7.4.4 训练不稳定

**症状：**

```
Loss曲线剧烈震荡：
Loss
 │    ╱╲  ╱╲
 │  ╱╲  ╲╱  ╲╱╲
 │ ╱  ╲      ╱  ╲
 │╱    ╲____╱    ╲
 └──────────────────→ Epoch
```

**原因与解决：**

#### 原因1：学习率太大 ⭐⭐⭐⭐⭐

```
学习率太大 → 步子迈太大 → 震荡

解决：
减小学习率
使用学习率调度（逐渐减小）
使用Warm-up（开始用小lr）
```

#### 原因2：Batch Size太小 ⭐⭐⭐⭐

```
Batch太小 → 梯度噪声大 → 不稳定

解决：
增大Batch Size
使用梯度累积（模拟大batch）
使用更稳定的优化器（Adam）

梯度累积示例：
每4个小batch更新一次
相当于batch size扩大4倍
```

#### 原因3：BatchNorm不稳定 ⭐⭐⭐

```
Batch Size太小 → BN统计不准 → 不稳定

解决：
增大Batch Size（至少16）
使用Group Norm / Layer Norm
冻结BN的统计量
```

#### 原因4：数据分布不均 ⭐⭐

```
某些batch特别难/简单 → loss震荡

解决：
Shuffle数据
平衡类别分布
使用分层采样
```

### 7.5.2 常见错误与陷阱

#### 陷阱1：过早优化

```

花几天时间在微调上

先快速建立基线
```

```
模型"记住"了测试集
真实性能可能只有80%

正确：
所有调参在验证集上进行
测试集只用一次！
报告那一次的结果
```

#### 陷阱3：忽略随机性

```
错误：
配置A：85.2%
配置B：85.3%
选B，因为更高

问题：
可能只是随机波动
实际差异可能不显著

正确：
每个配置训练3-5次
报告均值和标准差
A：85.2±0.5%
B：85.3±1.2%  （方差更大！）
实际上A可能更稳定
```

#### 陷阱4：不记录实验

```
错误：
改了学习率，效果不好
想改回去，忘了之前的值
浪费时间重复实验

正确：
用实验管理工具（如Weights & Biases、TensorBoard）
记录所有配置和结果
可以回溯查看
```

#### 陷阱5：迷信复杂方法

```
错误：
"我要用最先进的XXXX方法！"
花大量时间实现复杂技巧

正确：
先让简单方法work
80%的任务，简单方法就够了
复杂方法是锦上添花，不是必须
```

```
1. 快速基线（1-2小时）
2. 调学习率（LR Range Test）
3. 调模型容量（根据过/欠拟合）
4. 加正则化（如有过拟合）
5. 学习率调度（精调阶段）
6. 集成学习（最后1-2%）
```

**避免陷阱：**
```
过早优化
在测试集上调参
忽略随机性
不记录实验
迷信复杂方法
```
